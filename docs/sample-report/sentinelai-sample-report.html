1. SQL Injection in product searchcritical
CategoryInjection
EndpointGET https://api.example.com/v1/products
Parameterq
CWECWE-89
OWASPA03:2021 – Injection
CVSS band9.0 – 10.0
The product search endpoint concatenates the 'q' parameter directly into a SQL query. A boolean-based blind injection was confirmed: payloads altering the WHERE clause changed the result set deterministically, and a time-based payload induced a measurable server delay.
Evidence
GET /v1/products?q=widget' AND 1=1-- - → 200, 42 results
GET /v1/products?q=widget' AND 1=2-- - → 200, 0 results
GET /v1/products?q=widget';SELECT pg_sleep(5)-- - → 5.1s response
Remediation
Replace string concatenation with parameterized queries / prepared statements. Add an allow-list validator for the search term and apply least-privilege database credentials so the web role cannot read unrelated tables.
References
  • https://owasp.org/www-community/attacks/SQL_Injection
  • https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html

2. Reflected Cross-Site Scripting in error pagehigh
CategoryCross-Site Scripting
EndpointGET https://www.example.com/search
Parameterquery
CWECWE-79
OWASPA03:2021 – Injection
CVSS band7.0 – 8.9
The search results page reflects the 'query' parameter into the HTML response without output encoding, allowing arbitrary script execution in a victim's browser.
Evidence
GET /search?query=<script>alert(document.domain)</script>
Response body contained the payload unescaped inside <h2>…</h2>
Remediation
Context-aware output encoding on all reflected values, a strict Content-Security-Policy, and framework auto-escaping (do not disable it for this view).

3. Insecure Direct Object Reference on invoice downloadhigh
CategoryBroken Access Control
EndpointGET https://api.example.com/v1/invoices/{id}
Parameterid
CWECWE-639
OWASPA01:2021 – Broken Access Control
CVSS band7.0 – 8.9
Invoice IDs are sequential integers and the endpoint does not verify that the authenticated user owns the requested invoice, allowing horizontal privilege escalation and disclosure of other customers' billing data.
Evidence
User A (invoice 1001) requested /v1/invoices/1002 → 200 with User B's data
Remediation
Enforce an ownership check on every object access, and switch sequential IDs to unguessable UUIDs as defense in depth.

4. Missing security headersmedium
CategorySecurity Misconfiguration
